# SCF — Symbolic Context Factorization

SCF is a correctness-first C++20 research code base for discovering
*anonymous* string categories and structure from tokenized text using no
tags, labels, probabilities, embeddings, neural models, or external runtime
libraries. The work has gone through several changes of direction; the
repository is organised by **research line**, one directory per line, in
chronological order, so that the code, results and report of each idea live
together and can be read (or ignored) as a unit.

## Repository map

```text
common/                               platform layer shared by every line (peak RSS, console, CRLF)
01_saturation_tree_induction/         v1.1–v1.4  global equivalence saturation + maximum-evidence
                                                 binary tree induction; synthetic benchmark; audits
02_oracle_category_recovery/          v2.0       category recovery from a membership oracle via
                                                 bounded contextual signatures (synthetic grammars)
03_shared_context_evidence_scaling/   v2.1–v2.2  shared exact-context evidence on real corpora at
                                                 nested scales; terminal × punctuation ablation
04_conservative_witness_merging/      v2.3–v2.3.1 frequency-free single-witness transactional merging;
                                                 clean-corpus (peS2o) replication with frame types
05_closed_world_refinement/           v2.4       closed-world contextual equivalence computed by
                                                 counterexample-guided partition refinement  ← current
docs/prompts/                         the task specifications that drove each round
cmake/                                shared CTest configuration
data/real/                            (git-ignored) downloaded corpora and the UD treebank
```

Each line directory contains `README.md` (direction, status, how it relates
to the other lines), `include/scf/` (public headers), `src/`, `tools/`
(experiment drivers and scripts), `tests/` (assert-based regression suite),
`results/` (committed experiment outputs) and `reports/` (the write-ups).
Library targets are linked `PUBLIC`, so a later line can build on an earlier
one without copying code: 04 reuses the v2.1 tokenizer from 03, and 05
reuses the v2.3.1 corpus loader and frame-type classification from 04.

## How the direction changed

| line | question | mechanism | outcome |
|---|---|---|---|
| 01 | When does surface substitution evidence uniquely determine unlabeled binary structure? | strict global equivalence saturation; raw-witness DP over projective trees | exact on controlled grammars; global equivalence collapses under lexical ambiguity and exact contexts are >90 % singleton on real text |
| 02 | Do bounded contextual signatures recover categories from a membership oracle? | `Sig_k(u) = {(L,R,Accept(LuR))}` on synthetic CCG-like grammars | exact (ARI 1.0) once `k` reaches the category embedding depth |
| 03 | How far does shared exact-context evidence converge on real text? | shared-context counts with frequency floor, hub cap, thresholds; held-out replication | evidence replicates but stays sparse; frequencies re-enter the loop |
| 04 | Can merging be done with no frequency at all? | one exact substitution witness → candidate; transactional composition check | the `(ε,ε)` frame merges every short complete span with `<num>`, headers and formula fragments; the flaw is the witness semantics, not the corpus |
| **05** | What does *closed-world* contextual equivalence over the observed language look like? | `u ≡_D v ⇔ ∀(L,R)∈C_D: [LuR∈D]=[LvR∈D]`, computed by splitting blocks on distinguishing contexts | see `05_closed_world_refinement/reports/SCF_V2_4_CLOSED_WORLD_REFINEMENT_REPORT.md` |

## Build and test

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
ctest --test-dir build --output-on-failure
```

Every line has its own test binary (`scf_tests`, `scf_oracle_v2_tests`,
`scf_real_v21_tests`, `scf_conservative_v23_tests`,
`scf_clean_corpus_v231_tests`, `scf_closed_world_v24_tests`); all of them
are registered with CTest and all must pass. Executables are placed under
`build/<line directory>/`, e.g. `build/05_closed_world_refinement/scf_closed_world`.
The code base is portable C++20 (GCC/Clang on Linux and macOS; MSVC,
clang-cl and MinGW-w64 on Windows through the `common/` platform layer and
the `scf_configure_target` CMake helper); Visual Studio project files are
generated by CMake and are not tracked.

## Current line: v2.4 closed-world refinement (quick start)

```bash
# corpus (deterministic fetch + structure-preserving preprocessing, ~200 MB)
python3 04_conservative_witness_merging/tools/prepare_clean_corpus.py pes2o data/real/pes2o_body
curl -L -o data/real/en_ewt-ud-train.conllu \
  https://raw.githubusercontent.com/UniversalDependencies/UD_English-EWT/master/en_ewt-ud-train.conllu

# synthetic oracle cases only
build/05_closed_world_refinement/scf_closed_world --oracle-only

# real-corpus ladder (three context universes per scale)
build/05_closed_world_refinement/scf_closed_world \
  --input data/real/pes2o_body.scs --corpus pes2o \
  --scales 100000,200000,400000,1000000,10000000,20000000 \
  --ud data/real/en_ewt-ud-train.conllu \
  --output-dir 05_closed_world_refinement/results/pes2o_structured
```

See `05_closed_world_refinement/README.md` for the semantics, the output
files and the comparison run against the v2.3 merger.

## Conventions kept across all lines

- **Nothing statistical enters discovery.** POS labels (UD English EWT) are
  loaded only after a partition is final and are used for evaluation only.
- **Determinism.** Every run is reproducible byte for byte (runtime and
  memory columns excepted); regression suites re-run ladders twice and
  compare outputs.
- **Old lines are frozen.** Reorganising the tree did not change any
  algorithm; the only source edits were default output paths and the
  per-line CMake files. Reports quote the paths that existed when they
  were written; each line's `README.md` gives the mapping.
